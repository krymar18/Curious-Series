Projects and Tools

Two things to walk away with: a few concrete project ideas so "we should do something with AI" turns into an actual starting point, and a map of tools people across Ampersand already use — most of which just need to be pushed a bit further.

Objective

Give teams a short list of project shapes to recognize their own work in, and a realistic picture of which tools already cover it.

Key idea

Most teams don't need a new tool. They need to recognize which of a handful of project shapes their idea actually is, then reach for what's already available.

Project Ideas

Fifteen shapes, grouped by what they actually do. Find the one that matches your idea before you start building.

Assistants & Guides

Something a person talks to, or is walked through.

  • Bounded assistant or agent. Helps someone complete one repeatable task through conversation — guided intake, routing, search, or calling other tools. Scope stays fixed; it doesn't wander outside its lane.
  • Knowledge retrieval assistant. Finds, summarizes, and cites the right internal policy, guide, report, or reference. Built for "where do I find..." questions that eat up someone's day.
  • Training or enablement companion. Walks a user through a process step by step, explains what each step does, checks whether they understood it, and adjusts based on how they're doing.

Analysis & Insight

Turning data into something a person can act on.

  • Data analysis or prediction project. Uses a defined dataset to classify, forecast, summarize, detect anomalies, or surface patterns that change a business decision.
  • Exception detection and alerting. Watches data, files, reports, or process outputs and flags what's unusual — missing values, mismatches, anything that needs escalation.
  • Reporting and narrative generation. Turns dashboards, spreadsheets, status trackers, or raw metrics into a business summary or variance explanation someone can actually read.
  • Decision-support analysis. Compares options, surfaces patterns or risks from a defined dataset, and hands a person what they need to make a better call. The person still makes the call.

Automation & Workflow

The process runs itself, AI or not.

Start here if you're unsure

A single AI step inside a normal automation is the easiest project type to ship, the easiest to audit, and the one most teams should default to before considering anything more open-ended. That's AI-enabled workflow automation below — everything else in the automation runs on fixed logic, and AI only touches one step.

  • AI-enabled workflow automationRecommended starting point — A Power Automate or Power Apps process where AI handles exactly one step — extraction, summarization, classification, drafting, or decision support — while everything else runs on fixed logic. Predictable, auditable, and low-risk to build.
  • Document intake and extraction workflow. Turns messy documents, emails, forms, PDFs, or spreadsheets into structured fields, classifications, summaries, or follow-up actions.
  • Triage and routing automation. Reads incoming requests, tickets, emails, or forms and figures out category, urgency, owner, next step, or what's missing.
  • Meeting-to-action workflow. Turns meeting notes or transcripts into owners, deadlines, open questions, risks, and the follow-up messages that need to go out.

Build Support

AI helping someone build something else.

  • AI-assisted automation build. A traditional automation, script, dashboard, or workflow built faster because AI helped with design, formulas, code, documentation, testing, or troubleshooting. The output isn't AI — the build process was.
  • Research and synthesis workflow. Gathers information from approved sources, separates fact from interpretation, and produces a briefing, comparison, or decision memo.
  • Automation design support. Uses AI to map out the process, generate formulas, draft scripts, write documentation, or create test cases for a traditional automation.
  • Quality-control support. Uses AI to inspect an existing workflow, checklist, dashboard, or script and point out gaps, edge cases, or places worth troubleshooting.

Tool Landscape

A practical map, not a course. The point is picking the right starting point and knowing when to ask for help.

Microsoft 365 stack

Copilot

Grounded chat, research, analysis, meeting prep, document summaries, spreadsheet help, and pulling context across Microsoft 365. Covers Copilot Chat, Researcher, Analyst, Excel support, Teams recap, and Notebook-style context that carries across a session.

Microsoft 365 Copilot documentation

Power Automate

Repeatable process automation with clear triggers, actions, approvals, notifications, and handoffs. Use it when the process is predictable enough to spell out step by step.

Power Automate documentation

AI Builder

For when a Power Automate flow or Power App needs exactly one AI step: extracting fields, classifying a request, summarizing an input, drafting a message, or producing structured output for whatever runs next.

AI Builder documentation

Power Apps

A lightweight front end for intake, review, approvals, or status tracking. Use it when the experience matters but a full custom application doesn't.

Power Apps overview

Office Scripts, VBA, and Excel macros

Repeatable spreadsheet transformations where a script gets the same result every time, instead of asking AI to redo the same steps by hand.

Office Scripts documentation

Beyond Microsoft 365

Claude

Advanced prompting, long-context analysis, writing support, coding help, and technical reasoning outside the Microsoft 365 toolset.

Claude docs

Claude Code or coding agents

For builders editing files, writing scripts, testing code, refactoring, or working inside a repository with real feedback from errors and test results.

Claude Code overview

Model Context Protocol (MCP)

A connection standard, not a tool you use directly. Worth knowing as the way AI tools plug into real systems, data, and actions without a custom connector for every integration.

Introduction

Prompt management and evaluation tools

Worth adopting once a team is versioning prompts, comparing outputs, or capturing feedback to test whether a prompt change actually improved quality before rolling it out.

Documentation & diagramming

Lucid (Lucidchart / Lucidspark)

Mapping a process, sketching a workflow, or diagramming a system before anyone writes a line of automation. Useful for planning a build, not just documenting one after the fact.

lucid.co

Scribe

Turns a repeatable click-through process into a step-by-step guide automatically. Record the process once; Scribe writes the instructions and captures the screenshots.

scribehow.com

Custom code

Python or JS automations

For when a process needs more flexibility than Power Platform's no-code tools allow: custom API calls, complex data processing, logic that doesn't fit a flow diagram. More setup work, but no ceiling.

Conclusion & Reflections

Take a moment to reflect — it's what makes the learning stick.

Key Takeaways
  • Fifteen project shapes cover most of what "we should do something with AI" turns into. Find the shape before you pick a tool.
  • A single AI step inside a normal automation is the easiest, lowest-risk project to ship. Default to it when you're unsure.
  • Most of the tool landscape is already in use at Ampersand in some form. The gap is usually depth, not access.
  • Custom code (Python/JS) buys flexibility the no-code Microsoft stack doesn't have, at the cost of more setup work.
  • Documentation and diagramming tools (Lucid, Scribe) belong at the planning stage, not just as an afterthought once something's built.
Reflection
  • Pick a project idea you've been circling. Which of the fifteen shapes does it actually match?
  • Is there a workflow on your team that's really just "automation plus one AI step" that's been treated as a bigger build than it needs to be?
  • Which tool on this list does your team already use, but only scratch the surface of?
  • Where would a Lucid map or a Scribe guide have saved time on your last build?
