Types of AI Solutions

Before building anything, you need to know what you're building. This page breaks down the four AI solution types — classical automation, predictive ML, generative AI, and agentic workflows — and gives you a quick way to decide which one actually fits a project.

Objective

Match the technology to the actual requirement — not the tool you already know, or the one that's trending.

Key idea

AI is not one thing. Four different solution types solve four different problems, and picking the wrong one costs more than it saves.

Question the data path first

Teams often arrive with a specific solution already in mind — an AND Platform export, a third-party integration, a familiar tool. That instinct is often right. But before accepting the data source as a given, it's worth asking whether it's the right path or just the familiar one. A solution that doesn't make sense for one project can make complete sense viewed across every active initiative.

  • Can we access the underlying data directly, instead of processing an export?
  • Would a structured data feed serve this project — and future ones — better than a file transfer?
  • Could working with affiliates or internal teams improve how data is structured at the source?
  • Would better data infrastructure here unlock AI capability for other departments too?

The four solution types below assume that conversation already happened. If it hasn't, have it first.

The Four Solution Types

Each type solves a different kind of problem. Expand each one to see when it fits, when it doesn't, and how it shows up at Ampersand.

Classical Automation

Executes a fixed script. Every step defined in advance. Identical output for identical input.

Use when Avoid when Ampersand examples
You can write step-by-step instructions before the process runs; inputs are structured and predictable; steps must run in a specific, unskippable order. The process changes frequently; inputs are unstructured or vary in format; exceptions can't be listed in advance. SCX file reformatting, regrouping AND Platform exports, cross-system scheduled data pulls, scheduled reports with fixed logic, fixed approval routing.
Strengths
  • Identical input always produces identical output.
  • Every step logged and auditable.
  • Low ongoing oversight once built.
  • Can call AI at one step for exceptions without losing determinism.
Weaknesses
  • Brittle — any process change needs a rewrite.
  • Can't handle inputs that vary in structure.
  • Fails when it hits something outside its defined scope.

Hybrid note

Automation can call an AI model at one specific step — say, to parse a malformed field — while keeping full control of the sequence. This is the most common real-world pattern, and it's covered in the Hybrid section below.

Machine Learning / Predictive Model

Finds patterns in historical data. Used to forecast, predict, classify, or group.

Use when Avoid when Ampersand examples
You have a large amount of historical data and a decision to make from it — forecast a value, predict an outcome, compare similarities, or group and categorize records. Can sit inside an automation to add targeted discretion. There isn't enough historical data to train on; the workflow or how you interpret the data changes fast; the output needs to be human language; you need full model explainability and the model type can't provide it; a wrong prediction would be high-compliance-risk and irreversible. Revenue-at-risk reports and forecasting, predicting inventory and avail availability, optimizing makegood offers, anomalous billing pattern detection, linear regression for market revenue likelihood.
Strengths
  • Trained narrowly on one task, not a general-purpose black box.
  • Can be validated against held-out historical data before launch.
  • Adds decision-making at one step inside an automation pipeline.
  • Data-cleaning investment often improves other processes too.
Weaknesses
  • Needs substantial, clean historical data — often the hardest part.
  • Needs retraining when underlying patterns shift.
  • Real upfront work to label data and define the target correctly.

Underutilized at Ampersand

Given the volume of data Ampersand sits on, predictive ML may be the most underused solution type here — forecasting, classification, and anomaly detection across ad ops data is a real, mostly untapped opportunity.

Generative AI / LLM

Large language models — GPT, Claude, Gemini, etc. Generate and process human language.

Use when Avoid when Ampersand examples
The input or output is human language — emails, meeting notes, chat threads, narrative documents; the task is understanding, drafting, summarizing, or extracting meaning from text; the input can't reasonably be represented as a table. Consistency is required — LLMs are probabilistic and won't repeat identical output for identical input; there's no way to guarantee human review before the output is acted on; the data is structured (automation plus ML will be cheaper and more reliable); an incorrect or inconsistent output would carry regulatory consequences. Meeting transcript summaries, client email drafts, policy and process Q&A, extracting fields from unstructured documents, any chatbot or conversational interface.
Strengths
  • Only solution type that handles genuinely unstructured human language.
  • Broad capability: drafting, summarizing, classifying, extracting, translating, explaining.
  • Fast to prototype — no training data required.
  • Can be embedded in automation for a single language-handling step.
Weaknesses
  • Probabilistic — never fully consistent.
  • Hallucination risk — confidently wrong outputs.
  • Expensive at scale compared to automation.
  • Limited auditability — can't fully explain a given output.

Data input warning

Screenshots and PDFs get used to justify a GenAI solution because they're "unstructured" — but ask why the data only exists that way first. Structured records usually exist somewhere, and fixing the data feed beats building an AI Band-Aid on a data transfer problem.

Agentic Workflow

An LLM given a goal and a set of tools. Selectively and probabilistically decides which automations to trigger at runtime.

Use when Avoid when Ampersand examples
Choosing what to do next is too complex or contextual to write as rules, even in theory; many possible actions exist and only a few apply per run; the task involves discovery, synthesis, or research where the right path depends on what's found. A specific sequence of steps must run in a specific order every time; the process is stable and fully specifiable in advance — automation will be faster, cheaper, and more auditable; a full audit trail of exactly why each step ran is required. Complex research tasks (internal or web), a troubleshooting agent that queries multiple systems and routes to the right resolution path, end-to-end handling of requests where which systems to query varies by request, a detailed research agent.
Strengths
  • Handles tasks that genuinely can't be scripted in advance.
  • Navigates variable inputs, multiple systems, and open-ended goals.
  • Combines LLM judgment with automation tools to get work done, not just generate text.
Weaknesses
  • Probabilistic — you can't guarantee which tool runs or in what order.
  • Harder to audit — tool selection varies per run.
  • A bad early decision can cascade.
  • Needs ongoing human checkpoints.

Most commonly confused pair

Automation vs. agentic gets mixed up more than any other pair in this guide. The difference isn't complexity — it's whether the execution path is known before the process runs. See the comparison below.

Automation vs. Agentic — The Key Distinction

Multi-step doesn't mean agentic. A 40-step automation with branching logic is still automation if every branch can be pre-written.

Classical Automation Agentic Workflow
Execution Fixed sequence, identical every run AI picks its own path at runtime — varies by run
Predictable next step? Always No — the agent decides based on what it finds
Handles unstructured input No Yes
Decision-making None — every branch pre-written Reasons about context in real time
Auditability High — every step logged Lower — tool selection varies per run
Oversight Low once built Ongoing — outputs need human checkpoints
Risk Low Medium–High

Hybrid: automation with AI components

The most common real-world pattern. A classical automation runs a defined sequence but calls an AI model at one or more specific steps — the AI is a component, not the orchestrator; it doesn't decide what happens next. Examples: an SCX processor that uses an LLM to fix malformed fields, then finishes the transform deterministically. A report workflow that runs an ML model to flag anomalies, then routes flagged items to a fixed review queue. An inbound handler that uses an LLM to pull structured data out of a client email, then hands it to rule-based routing.

How to Choose

A practical way to work out which solution type actually fits.

The discretion test

Before picking any technology, ask: is the discretion in this process a genuine requirement for a good outcome, or just a side effect of humans having always done it? If consistency would produce better results, that's classical automation. If reasonable people given the same inputs would legitimately choose differently, you're in AI territory.

  1. Does the task require genuine judgment — decisions that depend on context or interpretation that can't be written as rules? No → classical automation, regardless of how the task is handled today. Yes → next question.
  2. Should it require judgment in an ideal world? No → this is a process design problem; standardize the process before picking any technology. Yes → you're in AI territory, and the nature of the judgment determines which type.

Quick decision flow

Work through in order. Stop at the first clear yes.

  1. Can you write every step and branch before the process runs? → Classical Automation.
  2. Do you have historical data and a defined outcome to predict or classify? → Machine Learning / Predictive Model.
  3. Is the input or output human language? → Generative AI / LLM.
  4. Is the decision logic too complex or contextual to express as rules, even in theory? → Agentic Workflow.

When in doubt, check whether automation with AI components (the Hybrid pattern above) solves it before committing to a fully agentic build. It's usually more predictable, cheaper, and lower-risk.

Common Mistakes

Six mistakes worth avoiding
  • Using an LLM where automation would do. If inputs are structured and logic is fixed, automation is faster, cheaper, and more reliable.
  • Treating a complex automation as agentic. Multi-step isn't agentic — if every branch can be pre-written, it's automation, no matter how sophisticated the logic.
  • Treating current discretion as evidence AI is needed. Ask whether the discretion should exist at all. An undefined process just gets its inconsistency scaled up by AI — define the process first.
  • Proposing agentic for auditable, sequential processes. If you need to explain exactly why the system did what it did, or steps must run in a guaranteed order, use automation with AI components instead.
  • Skipping hybrid as an option. Automation with AI components often beats a fully agentic build — more predictable, cheaper, easier to audit.
  • Accepting a screenshot or PDF as inevitable. The underlying data is usually structured somewhere. Fix the data feed before building an AI layer to read images of it.

Conclusion & Reflections

Take a moment to reflect — it's what makes the learning stick.

Key Takeaways
  • Four solution types solve four different problems: automation, predictive ML, generative AI, and agentic workflows.
  • The real question isn't "should we use AI" — it's whether the process needs consistency (automation) or genuine judgment (AI), and which kind.
  • Multi-step doesn't mean agentic. Agentic means the AI chooses its own path.
  • Hybrid — automation with one AI step — is the most common real-world pattern and often beats a fully agentic build.
  • A screenshot or PDF is rarely the real reason to reach for GenAI. Check the data source first.
Reflection
  • Think of a recent AI idea pitched at Ampersand. Which of the four types was it actually asking for?
  • Has your team defaulted to a familiar tool — an export, an integration — without asking if it was the right data path?
  • Run a process you own through the Quick Decision Flow. Where does it land?
  • Where might "hybrid" — automation with one AI step — solve something you've been treating as all-or-nothing agentic?
