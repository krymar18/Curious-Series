Copilot in SharePoint

A practical reference for Copilot’s SharePoint-specific features — page authoring, site agents, metadata intelligence, and the governance considerations that determine whether AI search helps or harms your organisation.

Objective

Understand how SharePoint’s content quality directly determines the quality of Copilot responses across all M365 apps — and build the metadata hygiene habits that make site agents actually reliable.

Key idea

SharePoint is not just an app where Copilot helps you. It is the data substrate that makes Copilot work across the entire M365 suite. The quality of your SharePoint content — how it’s named, tagged, and permissioned — directly determines the quality of every Copilot experience across every other app.

Features

Page authoring, site agents, metadata intelligence, and governance tools — grouped by what they enable and what they require to work reliably.

Page Authoring — Creating SharePoint Pages with Copilot

Content authors can create SharePoint pages and news posts from a description, a template, or existing source files. Pages save as private drafts by default — an intentional governance choice.

Page Creation from Source Files M365 Copilot
Excellent at
  • Converting existing Word documents, meeting memos, or project briefs into structured intranet pages
  • Creating news posts from a plain-language prompt when no source document exists
  • Repeating page types with templates: team updates, news posts, project briefs, FAQs, events
Better avoided for
  • Publishing without human review — the default private draft exists for a reason; always review before publishing
  • Treating generated content as final — section-by-section refinement produces better results than one-shot generation
  • Very long or conflicting source documents — Copilot may present proposed decisions as agreed outcomes

Exercise — Page Creation with Source Files
  1. Find a Word document or PDF in your SharePoint describing a project, process, or team initiative.
  2. Open a site where you have edit access. Click + New → Page with Copilot.
  3. Choose ‘Reference source files’ and attach the document. Write a short prompt describing the page’s purpose and audience.
  4. Review the draft: one section that is accurate, one that needs rewriting, one structural choice you would change.
  5. Select a text section and use Auto-rewrite to change its tone. Compare before and after.
  6. Save as private draft. Do not publish until you have reviewed the full page.
  7. Reflection: How long did the initial generation take vs building the same page manually? What still required human judgment?
Site Agents — Conversational Knowledge Bases on SharePoint Sites

Any site editor with M365 Copilot can create a site agent — no IT involvement, no code. It turns a document library into a knowledge base that answers natural-language questions grounded in that site’s content.

Creating & Configuring Site Agents M365 Copilot
Excellent at
  • Answering natural-language questions grounded in a specific document library or hub site
  • Filtering by metadata columns when documents are properly tagged — dramatically more precise than keyword search
  • Scoping narrowly to a single library or broadly to a whole hub site and its associated sites
Better avoided for
  • Libraries with no metadata, generic file names, or inconsistent column values — agent quality directly reflects metadata quality
  • Querying SharePoint List item data — site agents don’t reliably filter list columns as of mid-2026
  • Publishing a site agent without testing it with questions you would not want answered — sensitive content may surface
Agent query: find active documents

List all documents in this library tagged as [Document Type] with a status of Active, sorted by most recently modified.

Agent query: document comparison

What are the key differences between the [Date A] and [Date B] versions of [document name]?

Exercise — Build a Site Agent
  1. Identify a SharePoint document library with at least 10 documents your team actually uses.
  2. Open the site and click the Copilot (sparkle) icon. Follow the creation flow. Scope to that library.
  3. Add three starter prompts reflecting real questions your team asks about those documents.
  4. Test with a question you already know the answer to — verify accuracy and cited source.
  5. Test with a question that requires filtering by type or date. Note whether response quality depends on document tagging.
  6. Reflection: What would you need to do to the document library to make this agent genuinely reliable for your team?
Metadata — The Critical Dependency M365 Copilot
Excellent at
  • Libraries with descriptive column schemas — Document Type, Status, Owner, Department, Date — produce dramatically better agent results
  • Descriptive file names (‘Q3 Fulfillment Report — October 2025’) that let Copilot understand content without opening the file
  • Consistent column values — one term per concept, not ‘In progress’, ‘Active’, ‘In Progress’ all meaning the same thing
Better avoided for
  • Libraries where files are named with version numbers and no description — Copilot cannot distinguish relevant from irrelevant documents
  • Expecting good agent results without metadata work — content is the same; metadata is the difference
  • Waiting for automatic metadata extraction to be GA before improving any library — manual improvements help now
Metadata audit prompt

Based on the documents in this site, what are the three most common questions our team would ask — and what does our documentation say about each? Flag any gaps where the documentation is unclear or missing.

Ampersand Spotlight — Using This Responsibly

SharePoint’s ethical questions are different from other apps. The concern is not individual feature misuse — it’s what deploying Copilot reveals about existing data practices.

Copilot surfaces existing permission debt

Every organisation that has used SharePoint for years has files accessible to more people than they should be. SharePoint’s search was imprecise enough that most people never found over-shared content. Copilot Chat’s semantic search makes it trivially discoverable. Copilot does not create new access problems — it surfaces existing ones. The ethical responsibility is to fix the permission model before deployment.

AI-generated pages need a named reviewer

A well-formatted SharePoint page looks authoritative regardless of whether it was written by a person or generated by AI. Every AI-generated page must go through a named content owner review before publication: accuracy of factual claims, whether decisions presented as final were actually finalised, and whether referenced policies are current. Never configure away the default private draft behaviour.

Test your agent with questions you’d rather not answer

Before publishing a site agent to a broad audience, ask it the questions you would not want answered — questions about salaries, personnel decisions, pending legal matters, or client pricing. If it returns answers, review whether those answers should be accessible to all users of the agent. If not, narrow the knowledge source scope.

Natural-language workflows run at machine speed

Workflows built by business users describing what they need in plain language may not go through the same review process as IT-built flows. Errors in automated workflows — incorrect triggers, wrong destination folders, unintended file deletions — run at machine speed and can affect large volumes of files before anyone notices. Require IT review for any workflow that moves or deletes files.

Practice Challenges

These aren’t feature walkthroughs. Each challenge combines multiple Copilot capabilities in a real scenario. Do them in the app.

01

The Metadata Audit

Open a SharePoint document library your team uses regularly. Assess it against the Copilot-ready checklist: do files have descriptive names? Are columns defined beyond Name and Modified? Open 5 random documents — can you tell from metadata alone what type of document it is, whether it’s current, and who owns it? Document the gaps and estimate how long it would take to address them.

The Agent Build

Conclusion & Reflections

Take a moment to reflect — it’s what makes the learning stick.

Key Takeaways
  • SharePoint content quality directly determines Copilot quality across all M365 apps — metadata hygiene is not an IT concern, it’s a Copilot quality concern.
  • Site agent output quality is a direct function of how well documents in the library are structured and tagged. Metadata is the difference.
  • AI-generated pages must go through a named content owner review before publication. Never configure away the private draft default.
  • Copilot does not create new permission problems — it surfaces existing ones. Fix the permission model before deployment, not after.
  • Test any site agent with questions you would not want answered before publishing it to a broad audience.
Reflection
  • If Copilot’s quality across all M365 apps depends on the quality of your SharePoint content, what does that say about information management work that has been treated as administrative overhead?
  • Copilot does not create new permission problems — it surfaces existing ones. Is that reassuring or concerning? What does it tell you about the state of your organisation’s data governance?
  • If a colleague reads an AI-generated FAQ answer on your intranet and makes a decision based on it that turns out to be wrong, where does the responsibility sit?
