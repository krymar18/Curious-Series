Evaluate a Document Against Specific Criteria

Run a systematic evaluation of a real document against explicit criteria — then ask for what is missing and rate findings by severity so you know what to fix first.

10 – 12 min Any proposal, report, or draft document M365 Copilot Premium
1
Define your criteria first
You
▶
Do this
Choose a real document — a proposal, a report, a job posting, a client-facing summary. Define 3–5 evaluation criteria before opening Copilot. Examples: is the ask clear? are claims supported? is the language inclusive? does it lead with the most important point? does it answer the reader's most likely question?
2
Run the evaluation
Copilot Chat or Word · Copilot
▶
Do this
Open Copilot with the document. Replace [list your criteria] with the ones you defined above:
Prompt 1 — Evaluate

Review this document against these criteria: [list your 3–5 criteria]. For each criterion: pass, partial, or fail — and one sentence explaining why. Rate each finding: must fix / worth fixing / minor.

◉
Look for
How many "must fix" items are there? If there are none, either the document is strong or the criteria were too easy. More than three "must fix" items means fix the structural issues first — fixing tone on a poorly structured document is wasted effort.
3
Find what is missing
Copilot Chat or Word · Copilot
▶
Do this
In the same thread:
Prompt 2 — Find what is missing

What important element does this document not address at all? What question would a critical reader have after reading it that the document does not answer?

4
Run the second pass
Copilot Chat or Word · Copilot
▶
Do this
Fix the single "must fix" item. Then run this last prompt:
Prompt 3 — Second pass

If I fix the issues you identified, what is still the weakest part of this document?

Key Takeaways
  • "Review this document" produces observations. "Review this against these criteria" produces findings. Always define the criteria before asking for evaluation.
  • False positives are common — ask for severity ratings so you can triage rather than treating all feedback as equal weight.
  • The second-pass prompt surfaces the structural issue the first evaluation caught around but did not name directly.
