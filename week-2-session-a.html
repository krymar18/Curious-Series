What LLMs Are Actually Good At

This session separates native language-model prediction from tool-augmented execution so people can tell when a model is guessing and when it is using a tool.

The core distinction

The document says two modes can produce the same-looking output, but they behave differently under the hood.

Aspect Native LLM Tool-augmented LLM
What it doesPredicts the most statistically likely next word from contextUses an external tool like a search engine, database query, calculator, or code interpreter
What it knowsOnly training data up to its cutoff dateCurrent information, precise calculations, or specific documents, depending on the tool
How it failsConfidently generates plausible text that is wrongFails when the tool returns bad data, is misconfigured, or when the query is bad
What it looks likeExactly like tool-augmented outputExactly like native output

Key teaching point

You usually cannot tell from the final answer alone whether the model retrieved information from a live source or predicted it from training data.

The letter-counting demonstration

Ask any LLM how many times the letter S appears in MISSISSIPPI. Many models answer incorrectly because they are predicting a plausible answer instead of counting letters.

If you ask the model to write a short script that counts the letter S, the code can compute the answer correctly every time. The model did not count; it generated something deterministic that did.

Copy prompt

How many times does the letter S appear in the word MISSISSIPPI?

Why it matters

When accuracy is non-negotiable and the answer is computable, asking the model to generate code, a formula, or a query is more reliable than asking it to answer directly.

Why this matters in practice

The document turns the distinction into a simple decision rule for work tasks.

If you ask the LLM to... What actually happens More reliable approach
Count specific thingsPredicts an answer from statistical patternsAsk it to write code that counts, then run the code
Add or calculate numbersPredicts what a correct calculation looks likeAsk it to write a formula or script and verify output
Recall a specific date, name, or figurePredicts what that information probably isSearch for the fact and use AI to interpret or apply it
Summarize a document you uploadedReads the actual document text in contextWorks well if the document is short enough
Analyze data in ExcelUses a code interpreter behind the scenesStill verify formula outputs for financial or compliance-critical data
Answer a question about today's newsPredicts from training data unless search is activeEnsure web search is enabled or search directly
Activity

Run the MISSISSIPPI count live, then ask the model to write code that counts any letter in any word. The contrast between direct prediction and deterministic code execution is the point of the demo.

Copy prompt

Write a short Python script that counts the letter S in any given word.

Key principle

When you need a precise answer to a computable question, ask the model to generate something that computes it. The model's strength is language. Precision is the tool's job.
